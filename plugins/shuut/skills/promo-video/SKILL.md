# Make a promo video end to end in shuut

Use shuut tools for each step: the results land in the user's shuut files, the cut becomes a project the user can open and fix in the shuut editor, and every paid step is priced in the same credits with `dry_run` first.

1. Plan with the user: goal, length, ratio (9:16 for reels, 16:9 for a presenter), script lines, and which shots are presenter, generated scenes or real captures. `plan_write` with `kind` "director" and a one-line `scene` drafts a timed shot list for free. Before creating anything paid, price every paid call with `dry_run: true`, add the `cost_credits`, show the user the total and wait for their OK. The presenter's price needs the speech file, so quote and make the speech first (after the user's OK for it), then quote the presenter, scenes and music together and ask again. On each real call pass its quoted `cost_credits` as `max_spend_credits`, so the price cannot rise above what the user approved.
2. Bring in the user's own files (screen captures, logo, product photos, recordings): the server cannot read local paths, so call `media_upload` with `files` and run the curl line it returns in your shell, then `media_confirm` with the `upload_ids` (see the upload skill, also when curl cannot reach the host: the shell has no network). That curl is shuut's own upload: use it even when the user asked to use only shuut tools. `media_upload_open` (the user picks files in a window) is only for when you cannot run shell commands. Every file becomes a `file_id`.
3. Voice: `generate_audio` mode "speech" with `text` (one file per line; `voices_list` for voices). Write each line for the seconds you planned: Korean is about 4-5 syllables a second, English about 2.5 words a second. Check estimated_seconds (one estimate per line, in text order) in the `dry_run` result and lengthen or shorten a line before making it; the real length is the output's `seconds`. For the user's own voice (only theirs), follow the voice-music skill in order: call `voice_clone_phrase` and show its `notice` first, the user records the phrase and you upload it, the user confirms in this conversation that it is their own voice and agrees, and only then `voice_clone_create` with a `name`, the uploaded recording as `audio`, the `phrase_token` and `consent: true`; read the script with the `vc_...` voice. Music: mode "music" with `prompt` and `seconds`. Sound effects: mode "sfx".
4. Presenter: `avatar_video_create` with `mode`, the speech `file_id` as `audio` and `consent`. It takes one audio file, but speech gives one file per line: for a presenter who says several lines, either write the presenter's part as one `text` with no line breaks (one file), or make one presenter clip per line and join the clips in step 7. mode "stock" uses a ready-made presenter (no photo; names in `get_preset_instructions` avatar-stock); mode "photo" makes the user's photo speak. `consent` is required, but false is accepted (shuut's terms already require the person's permission); pass `consent: true` only when the user has confirmed in this conversation that the person whose voice or face is used agreed. Never assume it. To pick a model, use a `models_explore` kind video row (ask for `fields` "full") with that `avatar_mode` as `model`.
5. Scenes: `generate_video` (text or a `first_frame`) and `generate_image` for stills; `director_create` for a multi-shot film. To continue from the end of an earlier clip, `video_frame` (free) gives its last frame as an image `file_id` for the next `first_frame`. Create only what the user approved in step 1.
6. Call `jobs_wait` on each job until `done` is true and keep every output `file_id`.
7. Assemble with `editor_save` (free, saved at once): `key` is the final output path, `media` names each `file_id`, `spec` places them (see the editor-save skill for every field) - `shots` for presenter, scenes and captures with a `transition`, `audio` items for the voice and for sound-effect files (give those files the role `sfx` in `media`, as `{"file_id": …, "role": "sfx"}`; an `audio` item has no `role`), `bgm` for music with `duck_under_vo_db: -10` so it dips under the voice, `captions` with a large `style`, `overlays` for the logo. To fill a 9:16 canvas from 16:9 shots, pass `background` `{"type":"blur","blur":30}` next to `spec` (an `editor_save` field, not a spec field). Text already burned into a capture cannot be erased: crop it out, cover it with a blurred masked overlay of the same clip, or put a caption box over it.
8. Give the user `open_url` (the editable project, private to their shuut account). To change the video later, start from your previous spec, change only what changed and save the whole spec again with the same `project_id` and `key`: that updates the project instead of adding one (an item left out is deleted).
9. When the user wants the MP4 (or WebM, GIF, M4A, WAV), call `editor_export` with the `project_id` and an `idempotency_key`; if `done` is false, call `editor_task_wait` with `task_id` until it is done. Tell the user it takes a while: the server renders without a GPU, so even a 5-second 1080x1920 video can take a few minutes, and one account renders one export at a time. The longest export is about 38 s of 1080x1920 video at 30 fps; a lower height does not make it longer: export a shorter `range` or a lower `fps`, or ask the user to export in the editor.
10. Optional: `social_publish` with an `account_id` from `social_accounts_list` and the exported `file_id` prepares a post; the user confirms it at `confirm_url`.

Example arguments for `generate_audio`:

```json
{ "mode": "speech", "text": "Meet the assistant that finishes your video for you.", "idempotency_key": "promo-vo-1", "dry_run": true }
```

## Made or edited elsewhere

If you cut or changed a video for the user with ffmpeg or another tool, upload the clean sources and the final render, then call `editor_save` with `media`, `spec` (or the ffmpeg commands you ran as `ffmpeg`) and the final render as `reference` (without asking if the user's instructions turned on shuut auto-save; otherwise offer it once per chat after handing over the video, not again after a no, see the autosave skill). Save only the final video (not intermediates, previews or candidates), and not if the user said not to. Saving is free (fair use: 300 new projects a day, updates not counted) and instant. The same video made again updates its project instead of adding one: always pass `key` = the final output file path, plus the `project_id` you got if any; `new` only when the user asks for a separate copy. If the save is refused because several projects match, pass the right `project_id`. Tell the user it is a private project in their shuut account and give its `open_url`. A finished clip with no recipe: `editor_save` with `video`. To change it later, use `editor_project_get` with `include_spec` and save again with `project_id` and `base_revision`.

## Money, consent and limits

- Editing, saving and exporting are free (daily limits apply). Voice, music, avatar, image and video generation cost credits: always `dry_run` first, show the total and create only after the user's OK, and use a unique `idempotency_key` per job; resending the same key returns the same job.
- A real person's face or voice (the user's photo, a presenter speaking someone's recording) must be the user's own or used with that person's permission; a cloned voice can only be the user's own. Pass `consent: true` only after the user confirms in this conversation. Voice cloning has its own consent: show the `voice_clone_phrase` notice first.
- A failed or cancelled job is refunded in full, except error.code outcome_unknown (see the price-first skill).
